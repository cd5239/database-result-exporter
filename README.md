# 数据库查询结果导出工具

面向“在能访问数据库的 Windows 服务器执行多份查询，再将完整结果 ZIP 回传分析”的便携工具。无业务库、客户表名或连接凭据预设；不自动改写脚本中的业务参数。

| 交付 | 用途 | 运行条件 |
| --- | --- | --- |
| 多数据库版 v2.3.0 | 多数据库查询导出、关键字查找和 SQL Server Excel 导入 | Windows x64，自带 .NET 10 Windows Desktop 运行时与驱动 |

多数据库版的目标部署基线为 Windows 10 1809 / Windows Server 2019 及以上 x64；具体系统支持取决于微软运行时及驱动，目标服务器仍需人工验收。不承诺所有数据库服务器版本、认证插件或特殊类型均兼容。

## 使用

[下载 Windows x64 发布包](https://github.com/cd5239/database-result-exporter/releases/download/v2.3.0/database-result-exporter-v2.3.0-win-x64.zip)。程序的「关于」窗口提供版本号和成都伍贰叁玖科技有限公司官网链接。

1. 完整解压交付 ZIP，在服务器本地双击根目录的「启动工具.cmd」。程序及运行依赖在 `runtime`，源码、测试与构建脚本在「源码」，示例、许可和核验说明在「资料」。
2. 选择数据库类型，填写服务器、端口、数据库、用户名和密码，测试连接。数据库名称默认留空。
3. 关系型数据库添加 `.sql`；MongoDB 添加 `.mongo.json`。可多选或拖放，按完整路径忽略大小写去重，仅添加、不自动运行。一次运行使用一种数据库和一个目标库，不能混跑 SQL 与 Mongo 查询定义。
4. 默认导出到首个脚本目录；移除首项跟随后继。可手动选择目录，后续添加脚本不会覆盖手动选择；重新勾选“按首个脚本目录”恢复自动。
5. 按列表顺序执行，每份脚本独立连接，同脚本各批次复用连接。失败继续下一份；取消时保留已有结果。回传整个时间戳 ZIP。

不保存数据库密码；不把完整连接字符串写入结果或日志。业务查询结果、服务器错误可能包含业务信息，应按业务文件保管。默认辅助拦截可能误报，也不是安全沙箱；实际只读限制由数据库账号权限保证。

## 关键字查找（v2.3.0）

填写当前连接后，点击主窗口上方的「关键字查找」。窗口自动连接并加载可访问的用户表或集合。勾选查找范围，输入关键字，点击「开始查找」。可全选，也可只选几张表。

- 默认按包含内容匹配，可勾选「整值匹配」。百分号、下划线和方括号按普通字符处理。默认包含可转换为文字的数字、日期等字段，取消「含数字、日期等字段」后只匹配文字、JSON 等文本字段。数字和日期的匹配文本采用数据库转换格式。
- SQL Server、MySQL、PostgreSQL、Oracle 在数据库端进行参数化匹配。大小写、重音及整值匹配的尾部空格处理遵循数据库和字段的比较规则。查找当前连接的数据库范围内可见用户表，Oracle 使用当前账号可访问的非系统表。视图、二进制和部分特殊字段类型不参与匹配，窗口显示跳过字段数量。
- MongoDB 按集合读取文档，匹配文字及可选的数字、日期、布尔、ObjectId 值，区分大小写。嵌套字段和数组用路径显示，例如 `["contacts"][0]["name"]`。不会执行 JavaScript。
- 一行结果对应一条记录，列出表 / 集合和所有命中字段。选择一行后，下方显示完整记录，双击可放大查看并复制。关系型记录用有序字段数组保留字段名、类型、字符串值和 NULL，MongoDB 保留 Canonical Extended JSON。摘要只截取显示，完整记录保留长文本与金额精度。
- 每表默认最多 100 条，可调整为 1 至 500 条；全部结果最多 1,000 条。MongoDB 每集合最多检查 10,000 份文档。达到记录或扫描上限会明确提示结果可能不完整，记录顺序由数据库返回。
- 使用主窗口的查询超时设置，支持取消。超时、权限不足和部分表读取失败会显示提示并继续后续表；取消后保留已找到的记录。查找期间禁止切换连接及关闭查找窗口，等待结束后可关闭。

该功能会读取所选范围中的数据，大表查找可能需要较长时间。建议先选少量表，再按需要扩大范围。日志记录操作及数量，不记录关键字或结果正文。新增查找功能经过本机回归，五种数据库的实际查找结果仍需在目标环境测试。

## 连接配置（v2.1.0）

数据库类型和连接配置放在连接区域第一行。支持同一类型的多套连接，也支持跨类型切换。

- 填写连接参数后点击“保存”，输入名称；“新建”添加另一套连接。通过类型和连接配置下拉框切换。
- 保存服务器、端口、数据库、用户名、认证库/SID、身份验证方式、加密/证书选项、超时和辅助拦截开关。已命名连接的修改也会在切换或正常关闭时自动保存；可随时点“保存”立即写入。
- 不同连接的密码独立保留在本次运行内存中，来回切换不会丢失或串用；关闭程序后密码不保留，重新打开需再次输入。配置文件的结构不含密码或完整连接字符串字段。
- 未点击“保存”命名的临时连接，仅在本次运行中保留；切换数据库类型也会恢复其临时填写。重新启动只恢复已保存的命名连接。
- 配置文件位于 `%LOCALAPPDATA%\DatabaseResultExporter\connections.json`，不会写在 EXE 所在目录或导出结果包内。移动 ZIP 到另一台服务器不会携带本机连接配置。
- “删除”删除当前连接配置，需确认；不会修改数据库或导出结果。读取损坏配置失败时保留原文件并禁止覆盖，窗口中仍可使用临时连接。
- 一次任务仍使用当前所选连接，并非并行向多个数据库执行；执行时禁止切换连接。脚本列表和导出目录继续按窗口现有操作管理，不保存到连接配置。

## 运行日志（v2.1.0）

窗口中的运行信息同步写入工具根目录的 `log\运行日志_yyyyMMdd.log`（UTF-8，按天分文件）。整理版的 `log` 与「启动工具.cmd」同级，程序首次记录日志时自动创建该文件夹。日志包含启动、操作进度、结果位置和错误摘要，已知会话密码和连接字符串会经过隐藏处理。服务器错误文本仍可能含业务信息。

“日志目录”打开保存位置。“清空当前日志”确认后清空当天日志文件与窗口显示，并记录一条清空提示；保留其他日期日志、连接配置和全部导出结果。任务进行中禁止清空。日志文件不可写时继续显示窗口日志并提示，执行导出不因此中止。CLI 静态检查和自检保持原来的报告文件接口，不创建 GUI 运行日志。

## Excel 导入（v2.2.0）

1. 在主窗口选择 SQL Server 连接配置，填写密码，点击右上角“Excel 导入（SQL Server）”。读取用户表后显示连接状态，选择目标架构和表。
2. 点击“下载 Excel 模板”。在“填写数据”页从第 2 行填写，使用“字段说明”查看类型、必填项、默认值和示例。模板排除自增长、计算、rowversion 和其他系统生成列。保留表头和工作表名称，编码、长整数与高精度金额按文本输入。
3. 点击“选择 Excel…”及“校验并预览”。按真实列名匹配，允许调整列顺序。必填列留空会报错，有默认值的列留空采用数据库默认值，其余可空列留空写入 NULL。忽略完全空白行，处理所有非空行（包括隐藏行）。支持普通 `.xlsx`，首版每份最多 5,000 个非空行、压缩文件最多 20 MB。公式与合并单元格需要改为普通单元格常量。
4. 校验查看格式、范围、文件内重复及可查询的普通唯一索引。错误页显示 Excel 行、字段或索引和原因，可保存 CSV。通过后可预览最多 50 行、20 列。若修改文件或切换表，请重新校验。
5. 点击“确认导入”，核对服务器、数据库、目标表和待写入行数，确认后提交一个事务。工具再次核对模板对应的表结构和文件指纹，并逐批校验实际新增数。约束错误或新增数不符会回滚整份文件。连接中断导致提交状态不明时，根据提示先核对目标表。

首版面向 SQL Server 2016 及以上的普通用户表，正式导入要求目标表的 SELECT、INSERT、VIEW DEFINITION 权限。带启用 INSERT 触发器的表暂缓导入。导入事务持有短时表级排他锁，以保证写入期间表结构与触发器状态稳定。模板适用于生成时选定的连接目标和结构，表结构变更后请重新下载。仅新增模式下，业务去重依赖数据库定义的主键和唯一约束。筛选唯一索引、默认值参与的键及其他约束由数据库在写入阶段检查。

支持普通字符、整数、小数、金额、浮点、布尔、日期时间、GUID 和十六进制二进制字段。遇到未支持的可写类型或加密字段时，界面会提示具体列。模板与读取均使用 Open XML SDK，运行服务器无需安装 Excel。运行日志记录生成模板和提交结果摘要。真实数据库导入和回滚待隔离实例验收。

## 各数据库的范围和区别

- SQL Server：账号 / Windows 身份验证，GO / GO n，多结果集，PRINT、完整错误及行号，decimal(38)、长整数、长文本与 NULL。不支持 SQLCMD `:r`、`:setvar`、`!!`。
- MySQL：账号认证，分号分隔普通 SQL，读取高精度 DECIMAL 和零日期；不支持 mysql 客户端 DELIMITER、SOURCE 等指令。存储程序定义和依赖 DELIMITER 的脚本不属于本版本的查询脚本范围。
- PostgreSQL：账号认证，普通 SQL、美元引号，NOTICE。所有列使用数据库文本协议读取，保留高精度 numeric、数组、JSON、bytea 等原始文本，避免 CLR decimal 溢出；这些类型不统一转为 SQL Server 的二进制 Base64 / 日期格式。不支持 psql 元命令；E'...' 反斜杠转义字符串及 COPY 数据段不在当前脚本兼容范围。
- Oracle：数据库框填 Service Name；使用 SID 时填“认证库/SID”，数据库框留空。普通 SELECT 可用分号分隔；DECLARE / BEGIN 等 PL/SQL 块须以独占一行的 `/` 分隔。NUMBER、CLOB、BLOB 通过驱动专用类型读取。不支持 SQL*Plus SET / SPOOL / @ 等指令、替代引号 q'...'、OUT 参数或手动绑定 REF CURSOR；不采集 DBMS_OUTPUT。TCPS 需服务器及证书配置配合，不能使用“信任服务器证书”跳过校验。
- MongoDB：目标库填“数据库”，认证库留空默认 admin；支持 find / aggregate 查询定义，禁止 `$out`、`$merge`，不执行任意 JavaScript/mongosh 脚本。当前连接界面面向单入口用户名密码认证，不提供 SRV、SSH 隧道、完整 URI 或集群拓扑编辑器。

MongoDB 查询定义示例（保存为 `.mongo.json`）：

```json
{"collection":"example","operation":"find","filter":{},"limit":100}
```

```json
{"collection":"example","operation":"aggregate","pipeline":[{"$match":{}},{"$limit":100}]}
```

limit 省略或为 0 表示不限制结果条数。查询超时和取消仍然生效；服务器执行取消的具体响应依赖驱动及服务器状态。

## 结果格式

关系型数据库沿用 formatVersion=1：manifest、每脚本摘要、全部结果集（含空集）的列元数据、行 JSONL、UTF-8 BOM CSV、状态及错误。JSONL 每行按列顺序保存数组，NULL 为 null，其他值保存为字符串。无截断；CSV 仅用于便捷查看，准确值以 JSONL 为准。CSV 危险公式文本加单引号。

MongoDB 使用 formatVersion=2：每行一份 Canonical Extended JSON 文档，保留 ObjectId、Decimal128、嵌套对象、数组和日期等 BSON 类型；CSV 使用所有文档的顶层字段并集，嵌套值用 Extended JSON。缺失字段与 null 在 CSV 均为空，原始文档仍区分。取消保留已完成文档及不完整标记。

## 编译和测试

多数据库版：开发机安装 .NET 10 SDK，运行 `scripts/build.ps1`（随 ZIP 分发的副本在「源码」目录下）。发布为自包含 win-x64 目录，运行服务器无需安装 SDK。命令行用法可从交付包根目录调用 `runtime/DatabaseResultExporter.exe`。驱动版本固定在 csproj 和 packages.lock.json。构建时使用 NuGet。

```powershell
dotnet build tests/Exporter.Tests.csproj -c Release
dotnet tests/bin/Release/net10.0-windows/Exporter.Tests.dll work/tests
DatabaseResultExporter.exe --selftest 输出目录
DatabaseResultExporter.exe --check-sql 报告路径 SQL文件路径...
DatabaseResultExporter.exe --check-script PostgreSQL 报告路径 SQL文件路径...
DatabaseResultExporter.exe --check-script MongoDB 报告路径 查询文件路径...
```

`--check-sql` 保持旧接口，仅按 SQL Server 规则检查。`--check-script` 的类型为 SqlServer / MySQL / PostgreSQL / Oracle / MongoDB。CLI 检查不连接数据库。

本地测试覆盖原有导出、拖放和目录逻辑、驱动加载、连接参数、脚本拆分、MongoDB 精确文档与取消保留等；本地离线通过不代表真实数据库或远程验收通过。当前新增数据库均待用户真实环境人工测试。未连接或修改生产数据库。

中间产物在 work；正式包在 outputs。Git 仅管理源码、测试、构建脚本和说明，排除查询结果、凭据、日志、依赖缓存与交付二进制。
